# レビューの採点基準

合格は「**必須条件をすべて満たし、かつ合計80点以上、かつ0点の観点がない**」。合格したものだけを人の最終レビューに回す。書式は `templates/review.md`。

## 必須条件(1つでも満たさなければ不合格)

| # | 条件 | 確認先 |
| --- | --- | --- |
| M1 | 最新の検証ラウンドで、全手順の判定が合格 | `jobs/<job-id>/verification/round-*.md` |
| M2 | 後片付け検証で、タグ付きリソースが0件 | 同上の C2 |
| M3 | すべてのリソースに `handson-job-id` タグが付く | IaC のタグ設定、本文の CLI コマンドの `--tags` |
| M4 | 見積もりが上限($1.00)以下で、本文に想定コストが USD で書かれている | `aws-cost.json`、本文の「所要時間と想定コスト」 |
| M5 | 構成案が人に承認されている | `jobs/<job-id>/approvals.md` |
| M6 | 本文にアカウントID・アクセスキーなどの機密値が含まれていない | 本文と IaC の全体 |

## 採点(100点)

### 再現性(30点)

| 点 | 基準 |
| --- | --- |
| 30 | 本文だけで最後まで実行できる。検証の備考に「本文にない操作をした」記録がない。コマンドはコピー&ペーストで動く |
| 20 | 本文にない軽微な操作(ディレクトリ移動など)が1〜2か所必要だった |
| 10 | 本文にない前提(ツールのインストール、権限など)が必要だった |
| 0 | 本文どおりでは完了しない |

### 正確性(25点)

| 点 | 基準 |
| --- | --- |
| 25 | 全手順に具体的な確認ポイントがあり、検証の出力と一致する。用語・仕様の説明が出典と一致する。本文とコードのリソース名が一致する |
| 15 | 確認ポイントが曖昧な手順(「正しく作成されたことを確認」など)が1〜2か所ある |
| 5 | 説明に誤り、または確認ポイントと実際の出力の食い違いがある |
| 0 | 重大な誤り(動作の説明が逆、存在しないオプションなど) |

### コスト明記(15点)

| 点 | 基準 |
| --- | --- |
| 15 | リソースごとの単価・量・金額の表がある。時間課金のリソースは「中断するなら先に後片付け」と注意がある。無料枠を考慮していないことが書かれている |
| 8 | 合計額だけ書かれている |
| 0 | 書かれていない |

### 削除手順(20点)

| 点 | 基準 |
| --- | --- |
| 20 | 作成と逆順の削除手順があり、各手順に確認ポイントがある。最後にタグ検索による確認がある。`cleanup-checklist` の該当項目(自動作成ロググループなど)が反映されている |
| 12 | 削除手順はあるが、確認ポイントかタグ検索のどちらかがない |
| 5 | IaC の destroy だけで、CLI で作ったリソースの削除がない |
| 0 | 削除手順がない、または検証で残骸が出た |

### 読みやすさ(10点)

| 点 | 基準 |
| --- | --- |
| 10 | `handson-writing` の文体ルール(です・ます、1文が短い、初出の用語説明、1手順1操作)に沿っている |
| 5 | 部分的に沿っていない |
| 0 | 手順と説明が混在して、何を実行すればよいかわからない |

## 指摘の書き方

- 指摘ごとに「場所(ファイルと見出し)」「問題(読者がどこで詰まるか)」「直し方」「手順やコマンドの変更を伴うか(伴うなら再検証が必要)」を書く。
- 他のハンズオンにも当てはまる指摘は「スキル追記候補」として印を付ける。人の承認後に `handson-writing` や `cleanup-checklist` に追記する。
